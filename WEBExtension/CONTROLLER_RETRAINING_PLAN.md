# Leakage-controlled SparseComm retraining implementation plan

Goal: retrain a task-adaptive communication controller on real HotpotQA and evaluate a frozen selected checkpoint on 300 held-out questions, retaining all null/negative results.

Architecture: preserve the previous routing, rationing, stopping and task-versus-resource objective. Replace manually differentiated Gaussian latent actions with a PyTorch categorical actor/critic whose actions are the actual executable graph and per-edge quota. This is a one-step contextual-bandit PPO controller, not a reproduction of the original continuous PPO architecture or a learned multi-round stopping system. Action zero selects the initial NoComm ensemble; other actions execute a selected sparse/broadcast support at a selected quota. Existing E1–E4 controlled interventions remain separate causal experiments.

Files: controller_splits.py owns authentic data and split manifests; learned_controller.py owns gold-free features, categorical actor/critic, clipped loss and checkpoints; controller_study.py owns real rollout collection, validation-only selection, frozen held-out runs and reporting; controller notebooks 09–11 provide execution steps. machine_connection.py accesses existing project credentials in memory without exporting them. All deliverables stay in WEBExtension.

Data: publisher-pinned HotpotQA fullwiki train (90,447 rows) for optimization/validation, development fullwiki for held-out evaluation. Default 300 optimization, 100 validation, 300 held-out and 12 invariant-pilot questions. Exclude the 100 known legacy evaluated development question IDs from the held-out set. Use answer-independent deterministic hash ordering and bridge/comparison quotas. Enforce pairwise ID, normalized-question, and candidate-document-title disjointness for optimization/validation/held-out/pilot. Candidate-document disjointness is stronger than necessary and changes representativeness; explicitly report it. Gold labels are used as training rewards or validation scores only, never controller features or routing decisions. Label-free source/title split protection does not rule out backbone pretraining contamination or paraphrased questions.

PPO: autograd clipped categorical surrogate, value loss, entropy bonus, gradient norm clipping, minibatches and KL early stopping. Reward = (answer F1 - initial ensemble F1)/100 - 0.05*(payload/full-broadcast-payload) - 0.02*(receiver calls/3). These coefficients are prespecified engineering choices, not universal optima. Stop/no-communication is an explicit action with zero extra calls. The one-step trajectory does not need multi-step GAE. Three optimizer seeds use the same frozen authentic initial responses; report seeds individually and question-clustered aggregate uncertainty.

Selection: evaluate deterministic policy on validation after each collection epoch, select maximum prespecified mean utility (tie favors earlier epoch), and freeze checkpoint hash before accessing held-out model results. Three named static candidates (CW, CCW, out-star) are selected only on validation, without claiming exhaustive best-static optimization. Test baselines include NoComm, self-update, selected static, random support matched on edge count/quota, and broadcast. Their prompts/costs are saved. Whole-policy comparisons may differ in calls and payloads; destination-only attribution remains E2.

Current protocol update: the configured Azure connection works. A 12-question transport pilot completed with 176 real responses. An actual provider content-filter refusal subsequently stopped training; the user explicitly authorized counting provider refusals as abstentions with reported costs. A controlled request exhausted its 2,048-token output cap before producing answer text, so every arm now uses a fixed 8,192-token cap. A fresh frozen run is required; different-cap requests are preserved as archived feasibility/cost evidence and are not borrowed as primary responses. Refused outputs retain exact raw provider bodies and provenance; malformed, truncated or unrelated API failures still stop. Unknown usage is not imputed as zero. No synthetic rollouts or borrowed development scores will be substituted for training.

Scientific reporting: 300 held-out examples is a feasible initial sample, not a guarantee of power, generalization, reviewer approval or positive findings. Report paired uncertainty, action/stop frequencies, actual adaptation and degeneration to a static support, full costs, and historical exposure/pretraining limits. Do not tune on held-out outcomes or enlarge the held-out set after viewing its results.
