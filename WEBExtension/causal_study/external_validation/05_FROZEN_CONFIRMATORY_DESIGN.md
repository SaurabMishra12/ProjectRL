## Architecture and prompts

For each context/backbone, obtain 3 independent stochastic initial proposals. Clone the same three states into a 3-call private-revision arm and a 3-call peer-revision arm. Private sees its own response and original sources. Peer additionally sees the other two agents' parsed answerability, answer and citation-index fields, in seat order. It gets no new documents, rationales, labels or oracle selections. Both revisions start from initials, never from each other. Hash-frozen order alternates which revision arm executes first. This identifies the specified peer-message bundle relative to private revision; equal calls do not imply equal tokens or latency.

Exact system/initial/private/peer prompts and JSON fields are in [frozen/protocol.json](/home/saurab/Documents/projectRLMAIN/WEBExtension/causal_study/external_validation/frozen/protocol.json), generated by [design.py](/home/saurab/Documents/projectRLMAIN/WEBExtension/causal_study/external_validation/design.py). Temperature 0.7, top_p 1, max 2048 output tokens including reasoning, one sample, nonstreaming, no stop string; gpt-oss reasoning effort low. Three initial draws use separate cache namespaces and no inter-seat reuse. Greedy identical prompts were rejected because they could make independent proposals trivially identical. Input cap 32768; any overflow stops launch for an amendment rather than truncating or selecting favorable rows.

The parser requires explicit booleans, strings and valid source-index lists. False means expressed abstention; empty true, true `noanswer`, invalid JSON and invalid indices are failures, not repaired answers. Provider refusal remains distinct. Four offline readouts use the same final proposals: ProjectRL-style plurality comparator, aware plurality, lexical-aware and strict majority. The first comparator is not an official MuSiQue aggregator. Rule/code and prompt hashes are frozen in [frozen/freeze_hashes.json](/home/saurab/Documents/projectRLMAIN/WEBExtension/causal_study/external_validation/frozen/freeze_hashes.json).

## Primary estimand and safeguards

Let U=1 for a substantive EM/alias-correct answer under sufficient evidence, or a valid system/expressed abstention under insufficient evidence; otherwise 0. For each question q and context s,

`D(q,s) = [U(peer,aware)-U(private,aware)] - [U(peer,original)-U(private,original)]`.

Primary model-specific interaction is `E_q[(D(q,sufficient)+D(q,insufficient))/2]`. Minimum meaningful absolute effect=0.05 custom-utility units. This is chosen as a prospective practical threshold, not imported from the old −7 pp estimate. Both contexts remain in one question cluster. Test model-specific means using a two-sided paired studentized mean test at Bonferroni alpha 0.025 each; report 97.5% question-bootstrap intervals and descriptive 95% intervals,10000 draws with seed 20261016. Never use a binary McNemar test for this four-cell contrast.

The average may cancel a supported-question gain against an unsupported-question loss. Therefore both D components, false-answer change, coverage/selective risk by context, and raw failure/refusal categories are mandatory. No favorable/safe conclusion is allowed from the average alone. `D(sufficient)-D(insufficient)` is a declared exploratory context interaction, not an uncorrected new primary. Report original official MuSiQue answer EM/F1 and grouped sufficiency beside custom U; they are not renamed equivalents.

Selection is independent of correctness, disagreement or beneficial outcome. Blinded semantic annotations do not remove inconvenient primary rows. Preserve benchmark-label ITT and report ambiguity sensitivity. Retain transport/parse failures; an arm with incomplete required outputs has utility 0 under the declared failure convention for every readout, with separate adverse bounds for missing paired cells. Refusal is observed, not a free retry. Unknown execution halts. If incomplete-data bounds include 0, do not make a confirmatory sign claim from a complete-case subset.

## Why this is not a pilot recommendation

The 1000-question specification has adequate modeled power only under some variance assumptions; conservative sensitivities exceed the available pool. Author-archive equivalence, annotation/adjudication, serving/tokenizer identity, real prices and fresh inference authorization remain gates. If the literature and competent-control checks leave only an implementation defect, stop rather than executing this specification. No existing E6 allowance applies.
