# Independent blinded source-support annotation

Status: PREPARED, NOT ANNOTATED. Each label file contains48 PENDING cases. No human or independent semantic judgments are claimed.

Use two independent annotators. Give reviewer A only blind_reviewer_A.jsonl, labels_A.jsonl and these instructions, and B the corresponding B files. Their cases have different hash order. Withhold the sealed key, benchmark answerability flags, references, decompositions, support flags, model proposals, method identities, readout results and paired-context links. Blinding is procedural, not access control: do not send the sealed files to annotators. Case IDs are opaque; evidence content can naturally reveal support.

First pass: using only the question and supplied sources, label SUFFICIENT, INSUFFICIENT or AMBIGUOUS. For SUFFICIENT, write an answer supported by the sources and the exact source IDs plus quotations needed to derive it. For INSUFFICIENT, identify the missing relation/entity needed for the requested conclusion; do not infer insufficiency solely because annotated support is absent. For AMBIGUOUS, state competing interpretations or unresolved alternate support. Record confidence LOW/MEDIUM/HIGH. World knowledge and web search are prohibited in this task because sufficiency concerns this packet. Source contradictions and evidence supporting an alternative valid answer must be recorded.

Lock both first passes before revealing any references. An adjudicator then resolves disagreements using the evidence, preserving both original labels and written reasons. In a separate reference-validation pass, reveal benchmark answer/aliases and assess whether those answers, an alternative answer, or neither is entailed. Do not change first-pass labels silently. Record disagreements and agreement rates; with only24 paired question identities, these are diagnostic estimates with question-cluster uncertainty.

The sample comprises24 hash-ranked MuSiQue-Full question identities, both contexts per question; it is disjoint from the20 pilot and1000 conditional confirmation questions. No model correctness, disagreement or favorable outcome selected it. Some cases may be straightforward: ambiguity must be discovered by annotation, never assumed from missing support metadata. Both contexts stay in the same question cluster for analysis. Semantically ambiguous rows in a later experiment remain in the primary benchmark-label ITT population and receive a separate sensitivity analysis, rather than outcome-based exclusion.

Existing ambiguous ProjectRL source cases remain available in the preserved next_phase source-support audit and its blinded packages. They are not independent replication. Historical annotation labels remain pending unless their original files explicitly show otherwise. This phase adds independently prepared benchmark packets, not invented completed labels.
