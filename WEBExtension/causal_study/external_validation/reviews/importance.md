## What matters, and what the current evidence supports

The important practical question is whether evaluations attribute an apparent benefit to communication when that benefit depends on treating abstention as an answer competing in a plurality. That can affect which system a practitioner purchases or deploys. Its significance increases if the choice also changes whether a system answers unsupported Web questions, because answer accuracy on answerable questions can improve while the system becomes less reliable on requests that warrant abstention.

The preserved analysis reports a clear counterexample inside one saved system: partitioned Broadcast minus NoComm changes from 8 to 1 EM percentage points when both conditions receive the same abstention-aware readout, with a lexical alternative yielding equal EM counts. This is a consequential correction to that comparison. The 87.5% attenuation is a ratio of two observed point gains; its size does not itself establish prevalence, external impact, or a new mechanism. The matched 1-point estimate and its interval also cannot establish equivalence or that communication is useless. See the preserved [decision](../../readout_reassessment/07_FINAL_SCIENTIFIC_DECISION.md).

For a benchmark in which every defined abstention receives zero answer EM, replacing an abstention that wins a plurality with a substantive candidate has an obvious opportunity to improve the metric. The substantive contribution cannot be merely that this replacement sometimes works. It would have to show that a consequential evaluation error recurs across independent implementations, or that an explicit and reusable contract resolves a real trade-off between communication, evidence support, coverage and justified abstention that existing evaluations leave unresolved.

The external GSM8K audit is useful as a boundary check. The selected public traces come from an independent codebase and several model directories, but numerical reasoning without a benchmark-defined unsupported condition does not establish Web QA transportability. Parser failures mapped to `None` must not be relabeled as expressed abstention or provider refusal. If those traces contain no relevant abstention state, an unchanged readout is an expected contract boundary, not a well-powered null replication of ProjectRL's abstention interaction. More models in one external repository also do not supply multiple independent evaluation implementations.

MuSiQue-Full could provide a more relevant construct check because its answerability labels refer to the supplied evidence setting. An answer can exist in the world while not being derivable from the supplied paragraphs. That distinction is directly relevant to retrieval-based Web QA. Benchmark documentation and evaluator inspection establish suitability only; they do not provide saved multi-agent predictions, human sufficiency judgments, or a replicated communication effect. Pending blinded annotations must remain pending. Missing annotated support alone must never be promoted to a semantic unanswerability label.

## Five outcome scenarios

1. **Broadcast still helps under matched aggregation.** Report the remaining benefit with its uncertainty and actual cost. The original gain can still be inflated by readout while communication adds value. A findings paper would concern the magnitude and stability of evaluation conclusions; a claim that communication is unnecessary would fail. The private-revision control is necessary before treating the extra benefit as specific to peer information rather than additional update calls.

2. **Communication offers little incremental value.** This would be useful only within stated datasets, backbones, evidence regimes and uncertainty. A point estimate near zero or a nonsignificant test is not population equivalence. An externally reproduced, well-powered result against a competent readout and call-count-matched private revision could matter for system expenditure. Repeating the current small estimate in the same pipeline would add precision without establishing that broader point.

3. **Abstention-aware voting helps answerable QA but harms unanswerable QA.** The simple repair is not generally safe. This outcome could motivate a meaningful evaluation-contract contribution if the benchmark has valid answerability labels and semantic support is checked. Report false-answer rate on unsupported cases, correct abstention, answer accuracy and the coverage/risk trade-off. A method that rejects almost everything can appear safe; a method that answers everything can improve answerable EM. Neither alone is evidence of better system behavior. An improved average over an arbitrary answerable/unanswerable mixture must not hide the trade-off.

4. **Models or datasets exhibit opposite effects.** Preserve the signs and uncertainty rather than averaging them into a preferred narrative. This could reveal informative boundary conditions if they were defined prospectively or tested on held-out data. Post-hoc explanations tied to a few models remain hypotheses. Opposite effects defeat a universal attenuation claim but can support a carefully bounded empirical evaluation paper when the heterogeneity is reproducible and operationally interpretable.

5. **The problem disappears under a standard, competent aggregator.** Stop presenting the current issue as a general communication failure or new theory. A reproducible implementation correction and recommended evaluation checks remain useful. A WWW main-track argument would then need evidence that the flawed contract is widespread and materially changes real conclusions, or a separate unresolved answerability interaction. Without that evidence, category C is the appropriate endpoint; spending money to recreate a known weak baseline is not justified.

Every outcome belongs in the report. None should become a reason to change the primary inclusion rule, select a favorable model, or suppress an external counterexample.
