# Feasibility and the minimum additional experiment

**No paid work is recommended now.** The new matched-readout analysis supplies the main missing counterfactual using existing outputs. It does not need an inference pilot to establish its arithmetic.

## Disposition of the source-association study

**Abandon the currently prepared source-association experiment as the next primary WWW study.** Preserve its manifest, source snapshots, mocks and reports. This is a scientific prioritization decision, not deletion of evidence or a claim that provenance is unimportant.

Its 12-question/24-finalizer-call cached pilot would estimate a narrow mapping effect on inspected states. Original source links are not independently adjudicated, target exchange can improve support, there are only 20 mechanically eligible conflicts among 300 old partitioned states, and the closest literature already intervenes on attribution/provenance. Even a conspicuous pilot effect would not establish a novel or naturally prevalent Web failure. The pipeline's readiness therefore does not justify spending.

At the old 20/300 yield, the previously calculated 825 accepted-question 80%-power scenario needs about 12,375 screened questions and 38,775 completions, exceeding the current fresh source pool. The corresponding 90% target is 1,100 accepted questions and 51,700 completions. Those are hypothetical five-point/0.25-discordance scenarios, not measured effects or necessary budgets. A24-call pilot is not a credible route around the missing construct validity or prior overlap. No part of the six unused E6 slots is authorized here.

## One conditional fresh confirmation for narrativeA

If that zero-call work supports a meaningful findings contribution, the smallest relevant prospective architecture is **three shared initial responses, three private self-updates and three Broadcast updates per fresh question**, evaluated afterward by all three locked readouts. There is no paid finalizer and no requirement that initial agents disagree. Every aggregate consumes exactly the same saved proposals within its condition.

Population: unexposed source-capable benchmark questions, selected before model generation using the gold-free document-validity rule. Source selection, prompts, model revision, decoding settings, candidate/node order and readout policies must be frozen. Do not select on correct-proposal availability, abstention frequency or future communication success. This is a broad replication population, not a necessity-qualified scarcity cohort.

Primary estimand for a confirmatory protocol could be the question-level readout interaction:

`E[(EM(Broadcast, aware)−EM(SelfUpdate, aware)) − (EM(Broadcast, original)−EM(SelfUpdate, original))]`.

Both revision conditions use the same frozen initial states and three recipient calls. Randomize their execution order within question, retain raw requests and all failures, and cluster every readout/arm within question. The NoComm comparison is available from the initial states as an essential secondary description. One primary endpoint/comparison must be declared; F1, lexical tie sensitivity, proposal ceilings and abstention/coverage are secondary diagnostics. Confidence intervals use paired question resampling. The interaction is not a binary outcome and should not be tested as if it were a single McNemar pair.

This estimand tests how the evaluation readout changes the measured effect of providing the defined peer packet beyond private revision. It does not isolate source citations from answer strings, semantic verification from imitation, or all dimensions of compute. Requested revision-call counts are matched; actual tokens and latency must be metered, not assumed equal. Those scope limits are part of the experiment, not defects to hide by adding a larger sample.

A genuinely confirmatoryN cannot be chosen from the old exposed effect alone. Define the minimum important readout interaction and a question-level variance/discordance sensitivity range, check provider failures and the task's answerability mix, then preregister a feasible target. The old 8-question E6 interaction is not its variance estimate. A20-question check cannot establish a WWW contribution. Repeated readouts, the shared/partitioned pair and three learned seeds cannot be counted as independent questions.

For a SparseComm superiority claim, this nine-call architecture is insufficient: it omits learned policies. Such a claim additionally needs a prospectively chosen frozen-policy evaluation against recipient-call-matched controls, including actual tokens and training/selection costs. Matching edge count and message quota alone failed to match recipients on 912/1,800 existing learned/MatchedRandom pairs. Do not add those policy arms until an independent contribution and a fair resource estimand are specified.
