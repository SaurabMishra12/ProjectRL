# API cost and call budget — frozen before inference

Authorization: at most **150 successful LLM completions and 180 HTTP inference attempts** across this E6/E7 pilot, including retries. No PPO or full evaluation. Only eight E6 questions are scheduled, with four primary cells and 18 physical generations per question (144 total). Initial generations are shared within placement across the two revision arms. Each reported cell logically includes six generations; summing four cell costs would double-count initial work. Paid E7 is deferred; unused quota is not a target.

The existing Azure v1 `gpt-oss-120b` deployment, base URL, temperature 0, max_tokens 8192 and context_limit 32768 are preserved in `../frozen/config.json`. The provider exposes a deployment alias rather than an immutable model snapshot. Temperature zero is a decoding setting, not an identical-output guarantee. Exact pinned tokenizer identity is saved separately. No other deployment is permitted by this runner.

One exclusive persistent ledger in `../paid_pilot/ledger.jsonl` serves the entire study. It counts each dispatch before sending; every completion-shaped response, including a refusal, consumes the completion cap. Malformed/truncated successful responses are retained and never regenerated automatically. Config cannot raise the authorized ceilings. A serial lock covers each request and a study lock covers the run. Raw requests contain no authentication headers. API keys are loaded through the existing project credential helper and never copied to artifacts.

Concurrency is one; minimum dispatch spacing is two seconds and actual latency can make it longer. The HTTP transport has no automatic retries or redirects. Only explicit HTTP429 rejections are retried, at most twice per scientific request, honoring Retry-After date/seconds and retry-after-ms. All retries spend attempts. Other explicit client rejections stop; timeouts, network errors and HTTP5xx execution uncertainty stop the entire study and block resume. No timeout is assumed free. Saved atomic responses recover without another HTTP call after a crash. A conservative aggregate reservation ceiling of 2,000,000 estimated input-plus-maximum-output tokens is an additional gate, including retry reservations; this is not billed usage or money.

Mocked source-complete messages projected 138,614 input tokens including 128 framing-reserve tokens per request, and 1,318,262 input-plus-maximum-output reserved tokens over144 requests. Mock messages cite all local sentences and therefore usually carry more source evidence than actual model-generated citations; actual prompts are preserved and usage measured. Historical same-model controller successes with reported output usage average264.48 output tokens, implying about38,085 output tokens over144 calls. This is a rough expectation, not a promise. The absolute output cap is1,179,648 tokens (144*8192), and every prompt is checked against the context limit before dispatch. Actual token usage includes provider reasoning where reported.

Consequently no invented dollar estimate or enforceable monetary ceiling is reported. Actual money remains unknown until an authoritative billing record is supplied. Completion, attempt, output and conservative token-reservation limits remain binding. A runtime departure that requires extra calls is not silently authorized.
