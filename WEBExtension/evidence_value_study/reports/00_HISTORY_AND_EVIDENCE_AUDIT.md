## Original architecture: what the implementation actually supplies

The current canonical legacy implementation uses three independently solving agents, controller-selected directed communication, revisions, and confidence-weighted voting. The NumPy actor/critic consumes five answer/text summary features plus confidence scores, previous weights, round, answer diversity, and historical accuracy. It outputs low-rank source/destination factors, query vectors, and a halt component. `W = sigmoid(H_src H_dstᵀ + 0.5)` with a zero diagonal determines routing/bandwidth. Reward combines correctness, token cost, Bernoulli sparsity KL, cycle, and halt penalties. These are operational objectives and proxies; the code does not by itself establish an information-theoretic preservation theorem.

The five summary features are normalized answer entropy, lexical Jaccard similarity, unique-answer fraction, reasoning-length variability, and consensus strength. Current communication uses weight-dependent sentence masking/dropout and pass-through modes. Query vectors are assigned to `CommunicationGraph.Q`, but the inspected communication execution does not consume them as learned semantic queries. Current token counting in the legacy utility is a word proxy, `max(1, int(words * 1.3))`, not provider billing or model tokenization. “Information retention” includes lexical/cosine-style diagnostics, whose values cannot be read as verified answer faithfulness or measured true mutual information.

The current legacy PPO derivative also needs care: in a flat clipped-surrogate region, the implementation still uses a nonzero clipped mean multiplier; its log-standard-deviation derivative uses the unclipped ratio. For example, ratio 1.5, positive advantage 1 and epsilon .2 yields a flat ideal clipped objective but a mean multiplier 1.2 in the source. This is a current implementation issue. Without checkpoint-producing source/version provenance it does not explain or invalidate any particular historical checkpoint's measured performance.

The newer Web controller is a **different instrument**: a PyTorch categorical contextual policy over a finite support/quota catalogue, with a separate clipped objective and reward/readout. Its E5 results cannot be described as a clean replication of the original continuous NumPy architecture. The new E9 interaction does not require retraining either controller.
