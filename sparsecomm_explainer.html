System Overview

What is SparseComm? A multi-agent reasoning system where N LLM agents collaboratively solve questions. Instead of sharing full messages (expensive), a PPO-trained controller learns which agents should communicate and how much — implementing an Information Bottleneck that balances accuracy against token cost.
Why does it exist? Standard multi-agent debate sends every agent's full reasoning to every other agent every round. This is O(N² × T) in tokens. SparseComm learns a sparse communication graph W[i,j] that blocks uninformative channels and compresses partially-relevant ones — reducing token cost by 40-70% while maintaining or improving accuracy.
How does it work? A PPO policy network observes the current state of all agents (their answers, confidences, reasoning overlap) and outputs: (1) edge weights W[i,j] controlling bandwidth, (2) semantic queries Q for content filtering, (3) a halt decision. Each edge weight maps to a bandwidth mode: BLOCK (0 tokens), PARTIAL (compressed), or FULL (pass-through). The reward combines task accuracy with token cost penalties and KL sparsity regularization.

Why: NVIDIA provides free API credits for research. DeepSeek v3.2 is a strong reasoning model that handles math (GSM8K), multi-hop QA (HotpotQA), and algebraic reasoning (AQuA).

Class: Agent

▶

Single LLM-powered reasoning agent

What: Represents one LLM agent that solves questions and incorporates peer communication. Each agent has a unique reasoning style (analytical, step_by_step, creative, careful, efficient) and maintains a history of responses across rounds.
Why: Different reasoning styles promote diversity in initial answers. The history enables consistency checking — agents that stay consistent across rounds get higher confidence. The agent is the atomic unit of the multi-agent system.
How: solve() builds a prompt via _build_prompt(), calls the LLM backend's generate(), and computes confidence via _compute_confidence(). The prompt includes the agent's reasoning style instruction, the question, and any context from peer messages. Confidence combines the LLM's self-reported confidence with consistency checking against previous answers.

Class: AgentPool

▶

Manages N parallel agents

What: Creates and coordinates N agents. Handles parallel execution using ThreadPoolExecutor and message routing between agents. Manages the two-phase solve pattern: independent Round 0, then iterative communication rounds.
Why: Centralizes agent management so the experiment pipeline doesn't need to know about threading, agent IDs, or style assignment. Ensures stable ordering of results regardless of thread completion order.
How: initial_solve() runs all agents in parallel via ThreadPoolExecutor. communicate_and_solve() receives filtered messages for each agent and runs them in parallel with rate-limit retry logic. Results are reconstructed in stable agent_id order via result_map[agent_id]. 
class AgentPool:
    def initial_solve(self, question, dataset_type):
        # Parallel: all N agents solve independently
        with ThreadPoolExecutor(max_workers=self.n_agents):
            for agent in self.agents:
                futures[executor.submit(agent.solve, question, None, dataset_type, 0)]

    def communicate_and_solve(self, question, received_messages, dataset_type, round_num):
        # Parallel: agents re-solve with filtered peer messages
        with ThreadPoolExecutor(max_workers=self.n_agents):
            for agent in self.agents:
                msgs = received_messages.get(agent.agent_id, [])
                futures[executor.submit(agent.solve, question, msgs, dataset_type, round_num)]

Class: CommunicationGraph

▶

Bandwidth-aware directed communication graph

What: Manages the N×N weight matrix W where W[i,j] controls how much of agent i's message reaches agent j. Implements the semantic bottleneck: sentences are embedded, attention-pooled, bandwidth-gated, and top-k retrieved to produce compressed messages.
Why: This is the core innovation — replacing full communication with learned sparse communication. Each edge weight maps to a bandwidth mode (BLOCK/PARTIAL/FULL), implementing an Information Bottleneck that maximizes task-relevant information while minimizing token cost.
How: transmit() implements the semantic bottleneck pipeline:
1. Split message into sentences (reasoning nodes)
2. Encode with SentenceTransformer → embeddings (S, d)
3. Attention pooling against centroid → compressed vector z
4. Bandwidth gate: z_gated = z × w_ij
5. Cosine similarity → top-k sentence retrieval
6. Order-preserved filtered message

Bandwidth Modes

ModeConditionBehaviorTokens
BLOCKw < 0.05Complete silence — no message sent0
PARTIAL0.05 ≤ w < 0.95Semantic bottleneck filters messageProportional to w
FULLw ≥ 0.95Complete pass-through, no filteringOriginal count
class CommunicationGraph:
    def transmit(self, sender_id, receiver_id, message, round_num, llm_backend):
        w_ij = self.W[sender_id][receiver_id]

        if w_ij < 0.05:
            return "", 0          # BLOCK
        elif w_ij > 0.95:
            return message, tokens  # FULL
        else:
            # Semantic Bottleneck Pipeline
            sentences = split(message)
            embs = SentenceTransformer.encode(sentences)
            z = attention_pool(embs, centroid, tau=1-w_ij)
            z_gated = z * w_ij
            k = max(1, round(w_ij * len(sentences)))
            top_indices = cosine_similarity(embs, z_gated).argsort()[-k:]
            filtered = " ".join(sentences[i] for i in sorted(top_indices))
            return filtered, count_tokens(filtered)  # PARTIAL

Class: SemanticStateEncoder

▶

Encodes agent state into 5 interpretable features

What: Converts the current state of all agents (their answers and reasoning) into a 5-dimensional feature vector that the PPO controller uses to make decisions. Purely mathematical — no API calls, no model inference.
Why: The controller needs a compact, interpretable representation of the current multi-agent state. These 5 features capture: how much agents disagree (entropy), how similar their reasoning is (Jaccard), how diverse their answers are, how much their reasoning lengths vary (confidence proxy), and how strong the consensus is.
How: Each feature is normalized to [0, 1] range. Entropy is normalized by log₂(N). Jaccard is pairwise word overlap. Diversity is unique/total answers. Length variance is coefficient of variation (std/mean). Consensus is majority fraction. 
def encode_state(self, structured_states) -> np.ndarray:
    # 1. Shannon Entropy — disagreement measure
    unique, counts = np.unique(answers, return_counts=True)
    entropy = -np.sum(probs * np.log2(probs + 1e-8)) / np.log2(n_agents)

    # 2. Jaccard Similarity — reasoning overlap
    jaccard = mean([len(A∩B) / len(A∪B) for A,B in pairs(text_sets)])

    # 3. Answer Diversity — unique/total (HIGH = disagreement)
    diversity = len(set(answers)) / len(answers)

    # 4. Length Variance — CoV of reasoning length
    length_var = min(1.0, std(lengths) / (mean(lengths) + 1e-8))

    # 5. Consensus Strength — majority fraction
    consensus = majority_count / len(answers)

    return [entropy, jaccard, diversity, length_var, consensus]

Class: IBController CORE

▶

PPO controller — learns sparse communication topology

What: The brain of the system. A PPO (Proximal Policy Optimization) agent that observes the multi-agent state and outputs: (1) edge weights W[i,j] via low-rank factorization, (2) semantic queries Q for content filtering, (3) a halt decision for early stopping. Trained end-to-end to maximize task accuracy while minimizing communication cost.
Why: Hand-crafted communication rules can't adapt to different questions. Some questions need full debate, others need silence. The PPO controller learns to dynamically allocate communication bandwidth based on the current state — achieving the Information Bottleneck optimum.
How: State encoding: SemanticStateEncoder (5 features) + per-agent features → SetTransformer → pooled representation z → concatenated with global features (12 total) → final state vector.
Action: Actor MLP outputs mean + learned log_σ for continuous exploration. Action is split into H_src, H_dst (low-rank edge weights), Q (semantic queries), halt_logit.
W computation: W = sigmoid(H_src @ H_dst.T + 0.5) — low-rank factorization.
Training: GAE(λ=0.95) for advantage estimation, PPO clip (ε=0.2) for stable updates, AdamW optimizer, entropy bonus for exploration.

Reward Function

R = 1.5 × task_reward    # Accuracy signal (0 or 1)
  - 0.5                  # Baseline offset
  - λ_info × token_cost   # Penalize token usage
  - λ_kl × KL(sparsity)   # Encourage sparse W (Bernoulli(0.1))
  - γ × cycle_penalty      # Penalize communication cycles
  - halt_penalty            # Penalize using all rounds

GAE Advantage Estimation

for t in reversed(range(n_steps)):
    is_done = transitions[t]['done']
    mask = 0.0 if is_done else 1.0
    if is_done:
        next_value = 0.0
        gae = 0.0
    delta = reward[t] + γ × next_value × mask - value[t]
    gae = delta + γ × λ × gae × mask
    advantage[t] = gae
    returns[t] = gae + value[t]
    next_value = value[t]

Class: PlattCalibrator IsotonicRegression

▶

Confidence calibration + per-agent accuracy tracking

What: Calibrates LLM self-reported confidence scores to true P(correct) using sklearn's IsotonicRegression. Also tracks per-agent historical accuracy and empirical variance for Bayesian voting weights.
Why: LLMs are poorly calibrated — an agent saying "Confidence: 0.8" is not actually correct 80% of the time. Calibration maps self-reported confidence to true accuracy, enabling better Bayesian voting and SPRT halting decisions.
How: During training, accumulates (confidence, is_correct) pairs. After each epoch, fits IsotonicRegression: ir.fit(confidences, labels). At test time, calibrate(conf) maps raw confidence to calibrated probability. Also tracks per-agent historical accuracy for multiplicative voting. 
class PlattCalibrator:
    def accumulate(self, agent_id, conf, is_correct):
        # Store (confidence, correctness) for fitting
        self._train_confs.append(conf)
        self._train_labels.append(is_correct)
        self._agent_corrects[agent_id].append(is_correct)

    def fit(self):
        # Fit IsotonicRegression: conf → P(correct)
        self.ir.fit(X, y)
        # Compute per-agent historical accuracy
        for aid, corrects in self._agent_corrects.items():
            self._agent_historical_acc[aid] = mean(corrects)

    def calibrate(self, conf) -> float:
        # Map raw confidence to calibrated probability
        return self.ir.predict([conf])[0]

Voting Functions

▶

weighted_majority_vote() — Bayesian multiplicative voting

What: The primary voting function. Combines: (1) numeric normalization (24 = 24.0 = 24.00), (2) Bayesian multiplicative voting with calibrated confidence, (3) spectral centrality weighting from W matrix, (4) stability discounting for flip-flopping agents, (5) Platt calibration for true P(correct).
How: For each candidate answer, computes log-posterior: log P(answer) = Σ log(θᵢ) for agreeing agents and Σ log((1-θᵢ)/(n-1)) for disagreeing agents, where θᵢ is calibrated confidence. Returns the candidate with highest log-posterior. For numerical answers (GSM8K/AQuA), uses confidence-weighted mode instead of averaging. 
def weighted_majority_vote(responses, dataset_type, W, agents, calibrator):
    # 1. Normalize answers
    normalized = [_normalize_for_vote(r.answer, dataset_type) for r in responses]

    # 2. Get calibrated confidence per agent
    confs = [calibrator.calibrate(r.confidence) for r in responses]

    # 3. Apply spectral centrality (trust agents others trust)
    if W: confs = spectral_vote_weights(W, confs)

    # 4. Apply stability discount (penalize flip-flopping)
    if agents: confs *= compute_stability_weights(agents)

    # 5. Bayesian multiplicative voting
    for candidate in unique_answers:
        log_p = sum(log(θ) if ans==candidate else log((1-θ)/(2))
                    for ans, θ in zip(normalized, confs))
        posteriors[candidate] = log_p

    return canonical_map[max(posteriors)]
